## 0. 한 줄 요약

**음성 파일이나 폴더를 창에 놓으면 원본 옆에 `.md`가 생긴다. 앱이 하는 일은 이것뿐이다.**
유료 Batch는 비용 면의 핵심이라 유지한다. 그래서 "아직 기다리는 작업"은 남지만, **끝난 작업은 남기지 않는다.**

---

## 1. 왜 다시 설계하나

사용 패턴은 이렇다. 음성을 전사하고, 한 번 확인하고, ChatGPT 프로젝트 같은 곳에 넣는다. **전사본을 다시 손볼 일이 거의 없는 일회성 작업이다.**

지금 구조는 "작업(job)을 관리하는 도구"에 가깝다.

- 홈 화면이 작업 목록(최근 항목)이고, 폴더마다 상태가 9단계로 나뉜다(준비됨, 제출 전, 제출됨, 전사 중 등).
- 여러 폴더 제출, 원격 상태 새로고침, 사용량, 예상 비용, 고급 메뉴(개별 변환, 재시도, 보관)가 있다.
- CLI도 이 단계들을 하나씩 노출한다(`convert / estimate / upload / status / wait / download / auto / stats`).
- 이 모든 것이 폴더 안 상태 파일 15종과 백그라운드 감시자에 기대고 있다.

모두 정상적으로 동작하지만, 위 사용 패턴에서는 거의 쓰이지 않는다. 런타임 준비(Python, SDK, ffmpeg) 쪽에서는 첫 실행 버그(B1~B3)가 반복해서 나왔다.

## 2. 비슷한 앱 조사

| 앱 | 방식 | 핵심 흐름 | 참고할 점 |
|---|---|---|---|
| MacWhisper | 로컬 Whisper, 네이티브 macOS | **창에 놓으면 확인 없이 바로 전사**. 여러 개를 놓으면 Batch 창 | 시작 전에 확인 단계를 두지 않는다. 내보내기 형식이 많지만 우리에게는 필요 없다 |
| Aiko | 로컬 Whisper, 네이티브 | 창에 놓기 하나. 설정이 거의 없다 | 극단적으로 단순하다. 일괄 처리는 의도적으로 뺐다(단축어로 대체) |
| Buzz | 로컬 Whisper, Qt | 가져오기 대화상자 → 작업 목록 → 뷰어 → 내보내기 | 작업 목록과 뷰어 중심이라 지금 날먹과 비슷하게 무겁다. 감시 폴더와 CLI가 있다 |
| Vibe | 로컬 Whisper, Tauri(웹뷰) | 파일 선택 → 전사 → 결과 화면. 일괄 처리 지원 | 웹뷰 기반 데스크톱 앱이 이 분야에서도 통한다는 사례다 |
| TurboScribe | 클라우드 웹 | 올리기 → 끝나면 알림 → 내려받기 | 클라우드 비동기 처리(우리 Batch와 같은 성격)를 **"끝나면 알려 준다"** 하나로 처리한다 |

공통점은 셋이다.

1. **놓으면 바로 시작한다.** 시작 전 확인, 예상 비용 화면, 단계별 진행이 없다.
2. **결과는 파일로 끝난다.** 앱 안에 결과를 쌓아 두는 기능(뷰어, 기록)은 편집이 필요한 도구에만 있다.
3. 비동기 처리는 **"대기 중" 표시와 완료 알림** 정도로만 보여 준다.

날먹은 Aiko의 단순함과 TurboScribe의 비동기 처리 방식을 합친 형태가 맞다.

## 3. 핵심 기능 (이것만 만든다)

### 3-1. 놓으면 시작
- 창(가능하면 Dock 아이콘)에 **파일 또는 폴더**를 놓으면 바로 처리 목록에 추가하고 시작한다. 여러 개를 한 번에 놓을 수 있다.
- 받는 입력은 MP4, M4A, MP3, WAV다. 폴더라면 그 안의 오디오(하위 폴더 제외)와 PDF 1개를 쓴다.
- 폴더 안 **PDF는 용어 참고자료로 자동 첨부한다**(기존 동작 유지). 전사 정확도에 실제로 도움이 된다.
- 시작 전 확인 단계는 없다. 예상 비용은 처리 목록 행에 작게 표시만 한다.

### 3-2. 처리 방식: 토글 하나
- 창의 토글 하나로 **무료**와 **유료 Batch**를 고른다. 선택값은 기억해 두고, 그다음 드롭부터 적용한다.
  - 무료: 등록한 무료 키를 돌려 가며 바로 전사한다(live).
  - 유료 Batch: 1시간에 약 74원. 보통 10분~1시간이 걸린다.
- 키가 한 종류뿐이면 토글은 그 방식으로 고정된다.
- **무료 한도가 바닥나면** 해당 행에 "남은 n분을 유료 Batch로 보낼까요? [보내기]" 버튼을 띄운다. 지금의 자동 혼합(mixed) 계획은 없앤다. 사용자가 한 번 누르는 것으로 대신한다.

### 3-3. 처리 목록: 진행 중인 것만 보여 준다
행 상태는 네 가지뿐이다.

| 상태 | 표시 | 동작 |
|---|---|---|
| 전사 중 | 진행 막대 | 취소 |
| Batch 대기 | 경과 시간 | 취소 |
| 완료 | ✓ | **열기 · 복사 · Finder에서 보기**, ✕로 목록에서 지움 |
| 실패 | 사유 한 줄 | 다시 시도, ✕ |

- 완료된 행은 앱을 끄면 사라진다. **기록과 최근 항목은 없다.** 결과는 원본 옆 `.md` 파일로 남아 있다.
- **복사**는 전사본 전체를 클립보드에 넣는다. ChatGPT에 붙여 넣는 용도로는 이 버튼이 가장 많이 쓰일 것이다.

### 3-4. Batch 대기와 재실행
- 창이 열려 있으면 30초마다 Batch 상태를 확인한다. 끝나면 `.md`를 저장하고 OS 알림을 띄운다.
- **창을 닫아도 Batch는 서버에서 계속 진행된다.** 앱을 다시 열면 기다리던 Batch를 확인해서 끝났으면 저장한다.
- 백그라운드 감시 프로세스는 두지 않는다.
- 대기 상태는 **앱 데이터 폴더의 `pending.json` 한 파일**에 둔다. 원본 폴더에는 결과 `.md` 말고 아무 파일도 만들지 않는다.

### 3-5. 결과 파일
- 파일을 놓았으면: `강의09.m4a` 옆에 `강의09.md`를 만든다.
- 폴더를 놓았으면: **폴더 안 오디오를 파일 이름 순서로 이어 붙여 `.md` 하나로 합친다.** 파일은 폴더 안에 `<폴더명>.md`로 만든다.
- 같은 이름의 파일이 이미 있으면 ` (2)`를 붙인다. 덮어쓰지 않는다.
- 형식은 Markdown 하나만 쓴다. 자막(SRT/VTT)이나 Word 내보내기는 만들지 않는다.

### 3-6. 키 설정
- ⚙ 버튼으로 시트를 연다. 무료 키는 여러 개, 유료 키는 하나 넣는다. 저장하기 전에 과금 없이 키 유효성을 확인한다.
- 키는 OS 키체인(macOS Keychain, Windows 자격 증명 관리자)에 저장한다.
- 처음 실행했는데 키가 없으면 드롭 영역 대신 키 입력 안내를 보여 준다.

### 3-7. 업데이트
- 앱을 시작할 때 manifest를 확인한다. 새 버전이 있으면 창 아래쪽에 한 줄 배너를 띄운다. 업데이트는 앱 payload(ZIP) 교체로 끝나고, 의존성은 다음 실행 때 `uv`가 lock에 맞춘다.

### 3-8. 없애는 것

| 지금 기능 | 처리 |
|---|---|
| 홈 작업 목록, 최근 항목, 상태 9단계 | 삭제. 진행 중인 행만 남긴다 |
| 여러 폴더 제출(`m`) | 삭제. 여러 개를 한 번에 놓으면 된다 |
| 원격 상태 새로고침(`r`), 감시자, 진행 상황 화면 | 삭제. 창이 열려 있는 동안 자동으로 확인한다 |
| 예상 비용 화면(`e`), 사용량(`u`), `stats` | 삭제. 행에 예상 비용만 작게 표시한다 |
| 고급 메뉴(개별 변환, 재시도 방식 선택, 보관) | 삭제. 실패 행의 "다시 시도" 하나로 대신한다 |
| 자동 혼합(mixed) 계획 | 삭제. 한도 소진 때 "유료 Batch로 보내기" 버튼으로 대신한다 |
| 모델 선택 | 화면에서 뺀다. 환경변수로만 바꿀 수 있게 한다 |
| TUI | 삭제. GUI로 대체한다 |
| CLI 단계 명령 9개 | `nalmeok <파일·폴더...> [--batch]`, `nalmeok doctor` 두 개만 남긴다 |
| 런처, 부트스트랩, Python 런타임 준비 | uv 하나로 줄인다(`review-2026-11.md` §3-1). ffmpeg는 이미 PyAV로 바꿨다 |

## 5. 기술 선택

### 5-1. 언어: Python 유지
Go도 검토했지만(단일 실행 파일, 런타임 준비 불필요) 다음 이유로 Python을 유지한다.

- **이미 있는 것을 다시 쓸 수 있다.** Batch 제출·조회, 무료 live 호출, 키 순환, 업로드 만료 처리, 프롬프트, 테스트 182개가 있다. 재설계는 대부분 **지우는 작업**이고, 남는 엔진은 옮겨 쓰면 된다.
- **오디오는 이미 해결됐다.** ffmpeg를 PyAV로 바꿨다(`e5788a5`). Go였다면 AAC 추출과 분할(ADTS)을 직접 만들어야 했다.
- **오픈소스로서의 접근성.** 기여자가 읽고 고치기 쉽고, `pip`/`uv`로 바로 설치해 CLI로 쓸 수 있다.
- **Gemini 공식 SDK의 기본 언어다.** 새 API(Batch 등)가 Python에 먼저 들어온다.

대가는 런타임 배포다. Python과 SDK를 사용자 PC에 준비해야 한다. 이것은 `review-2026-11.md` §3-1의 **uv 일원화**로 줄인다. 런처는 `uv run` 하나만 하고, 부트스트랩·PBS·`ensure_sdk` 재시작 경로는 없앤다.

### 5-2. GUI: pywebview (OS 내장 웹뷰)
웹뷰가 무거울 거라는 걱정이 있었는데, pywebview는 Electron과 다르다. Chromium을 넣지 않고 **OS에 이미 있는 웹뷰**(macOS WKWebView, Windows WebView2)로 창만 띄운다.

| 후보 | 장점 | 단점 |
|---|---|---|
| **pywebview** (추천) | 추가 크기가 작다. 한글은 OS 폰트로 나온다. 화면을 HTML/CSS로 짜서 LLM과 나눠 작업하기 쉽다 | 파일 드롭 때 전체 경로를 받는 기능은 5.x부터라서 검증이 필요하다 |
| tkinter | Python에 들어 있어 의존성이 0이다 | 파일 드롭에 `tkinterdnd2`(네이티브 바이너리)가 필요하다. 보기 좋게 만들기 어렵다 |
| PySide6(Qt) | 기능이 가장 풍부하다 | 설치 크기가 100MB를 넘는다 |

- Windows 10/11에는 WebView2가 기본 설치돼 있다.
- 화면(`frontend/`)은 프레임워크 없이 HTML/CSS/JS 몇 파일로 만든다. Python과는 pywebview의 `js_api`로만 주고받는다.

### 5-3. 모듈 구조 (DeepSeek과 나눠 작업하기 쉽게)

```
nalmeok/
  media.py     입력 스캔(파일·폴더 → 오디오 목록 + PDF), PyAV 추출·분할
  plan.py      입력 → 요청 단위 계획, 예상 비용 (순수 함수)
  gemini.py    업로드(48시간 만료 처리), live 호출, Batch 제출·조회·결과
  keys.py      키 저장(OS 키체인 검토), 무료 키 순환(429), 유효성 확인
  queue.py     처리 목록 상태, pending.json, 실행 스레드
  output.py    결과 병합, .md 쓰기, 이름 충돌 처리
  gui.py       pywebview 창, js_api (queue만 호출)
  cli.py       nalmeok <경로...> [--batch], nalmeok doctor
  update.py    manifest 확인, 앱 payload 교체
  frontend/    index.html, app.css, app.js
```

- 의존 방향은 `gui/cli → queue → gemini · media · plan · output → keys` 한쪽으로만 흐른다.
- 각 모듈의 함수 시그니처와 테스트를 먼저 정한다. 이렇게 하면 구현을 모듈 단위로 넘길 수 있다.
- 지금의 `screens.py`, `term.py`, 감시자 코드, 폴더 안 상태 파일 15종은 옮기지 않고 지운다.
