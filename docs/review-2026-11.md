# 전체 코드 리뷰와 구조 단순화 계획 (2026-11-02)

> **제품 재설계 진행 중**: [`redesign-2026-11.md`](redesign-2026-11.md)(초안)가 확정되면 이 문서의 작업 모델·감시자·대시보드 계획(C6·C7·C12, §3-3, D3·D4)은 그 문서로 대체된다. 결함 기록(§1)과 이미 반영한 수정은 그대로 유효하다.

설치(installer)부터 첫 실행, 전사, 결과까지 전체를 검토한 기록이다. 기준은 `cac1a1e`다. 회귀 위험보다 **기능별 안정성·단순성·UX**를 우선한다.

- 채택한 방향: **uv로 런타임 일원화(§3-1, uv는 첫 실행 때 내려받음)**, **PyAV로 ffmpeg 제거(§3-2)**, **백그라운드 감시자 제거(§3-3)**.
- 가벼운 수정은 바로 반영했다(§1). 구조 변경은 §5 결정에 따라 단계별로 진행한다.

---

## 0. 요약

기능마다 방어 코드는 꼼꼼하지만 **같은 문제를 여러 경로로 각각 풀고 있어** 복잡도가 쌓였다. 대표 사례는 세 가지다.

- Python 준비가 PBS와 venv 두 벌이다.
- 전사 엔진이 batch, live, mixed 세 벌이다.
- 폴더 안 상태 파일이 15종이다.

첫 실행 버그 B1~B3은 모두 이런 경로들이 **맞닿는 이음매**에서 생겼다. §2는 이런 중복을 15가지로 정리한 목록이고, §4는 그 결과로 제안하는 모듈 구조다.

## 2. "같은 문제를 여러 경로로" 목록

각 항목은 **현재 구현 위치 → 통합 방향** 순서다. 숫자는 코드에서 직접 센 값이다.

### C1. 런타임(Python·SDK) 준비: 4곳
- 현재: `nalmeok.cmd`의 `find_python`, `bootstrap.ps1`(PBS 다운로드·해시·압축 해제·`current.txt`), `bootstrap.command`의 `find_python`(후보 경로 6개 + PBS), `update.ensure_sdk/restart/venv_path/project_python/python_usable/update_sdk`.
- 이 이음매에서 생긴 결함: B1, B2, B3.
- 통합: **uv 하나**(§3-1). `uv.lock`이 Python 버전과 SDK 해시를 결정한다.

### C2. 다운로드와 해시 검증: 해시 7벌, 다운로드 4벌
- SHA-256: `bootstrap.ps1 Assert-Hash`, `bootstrap.command`(shasum), `update.file_sha256`, `update.apply_update`(인라인 hashlib), `release_common.sha256_file`, `build_macos.sha256`, `build_windows.sha256_file`.
- 다운로드: `Invoke-Download`, sh의 curl, `update.download_bytes/download_file`, `build_windows.download`.
- 통합: 런타임은 uv가 받는다. 앱이 직접 받는 것은 앱 payload 하나만 남으므로 `update.py`에 함수 하나면 된다. 빌드 쪽은 `release_common`으로 모은다.

### C3. ffmpeg 확보: 5가지 경로
- 현재: `find_tool`(`NALMEOK_FFMPEG` → 앱 폴더 → PATH), `ensure_ffmpeg`(manifest에서 160MB), `bootstrap.ps1 -Ffmpeg`, 오프라인 번들, macOS는 brew 안내.
- 통합: **PyAV**(§3-2). 외부 실행 파일이 아예 없어진다.

### C4. "이 폴더에 처리할 오디오가 무엇인가": 6가지 정의
- `_count_media`, `estimate_files`, `needs_conversion`, `list_media`, `convert`, `browse_folder`가 각자 `iterdir()`로 다른 규칙을 적용한다. **B11이 바로 이 불일치에서 나온 버그다.**
- 통합: `scan_folder(folder) -> FolderMedia(audio: [Track], pdf, unconverted_mp4)`를 한 번만 계산하고 모두가 그 결과를 쓴다.

### C5. 오디오 분할과 계획: 3벌
- `prepare_live`와 `prepare_mixed`의 분할 루프가 거의 같다. `mixed_preview_lines`는 미리보기를 위해 분할을 ffmpeg 없이 **한 번 더 흉내 낸다**.
- 통합: 순수 함수 `plan_units(tracks, chunk_seconds)`가 **미리보기와 실제 실행 모두에** 같은 계획을 돌려준다. 실제 자르기는 실행 단계에서만 한다.

### C6. 전사 엔진: 상태 머신 3개
- batch(`_upload/_download/recovery/retry_batch/retry_live`), live(`_live_transcribe`), mixed(`_mixed_run/submit_mixed_paid/wait_mixed_paid`).
- 그 안에서도 같은 코드가 반복된다.
  - 업로드와 만료 검사가 3벌이다. batch 쪽만 만료 검사가 빠져 있었다(B9).
  - `generation_config`가 3벌, 구버전 SDK용 thinking 폴백이 2벌이다.
  - "결과 파일 비교 → 저장 → 정리" 마무리가 3벌이다.
  - 결과 병합이 3벌이다(`merge_jsonl`, `merged_mixed_text`, live 병합).
- 통합: **하나의 Job에 Unit 여러 개**를 둔다. 각 Unit은 `backend: free|paid`다. 실행기는 하나이고, free unit은 live 호출, paid unit은 Batch로 묶어 제출한다. "무료만", "유료만", "혼합"은 배분 정책 차이일 뿐이다.

### C7. 상태 파일 15종과 JSON 읽기 코드 8곳
- `.gemini_batch*` 9종, `.gemini_live*` 3종, `.gemini_mixed*`, `.nalmeok-archive`, `.nalmeok-drop-source`, `.nalmeok-converted`가 있다. 이와 별도로 `json.loads(path.read_text())`를 직접 쓰는 곳이 8곳이다(`read_json_object`가 있는데도 우회한다).
- 통합: 폴더 안에 **`.nalmeok/` 디렉터리 하나**를 둔다(`job.json`, `results/`, `audio/`). 보관은 디렉터리 이름을 바꾸는 것으로 끝난다. 읽기와 쓰기는 `JobStore` 하나만 거친다.

### C8. 키 선택: `key` 변수를 66곳에서 넘긴다
- 화면 함수들이 `key`를 인자로 받아 다시 넘긴다(`(folder, key` 66곳). 그런데 실제 사용할 키는 결국 등급(tier)으로 다시 고른다.
- 레거시 단일 키 API가 남아 있다: `saved_key`, `remember_key`, `forget_key`, `current_key`, `key_source`, `paid_key_for_batch`, `key_for_tier`, `ensure_paid_key`.
- 등급 검사가 `cli`, `run_with_client`, `start_watcher` 세 곳에 따로 있다.
- 통합: **`KeyPool`**. `pool.client("free")`, `pool.rotate_on_429()`, `pool.has("paid")`를 제공한다. 화면은 키를 들고 다니지 않는다. 저장소는 `keyring`(OS 키체인) 사용을 검토한다.

### C9. 진행 표시: 5가지 방식
- `live_progress` 스레드, `wait_for_completion`의 `draw()`, `convert_progress_line`, `download_file`의 % 출력, `"\r\033[K"` 직접 출력 12곳, `capture_logs/live_status`로 logger를 바꿔 끼우는 방식.
- 통합: `Reporter` 인터페이스 하나(`step()`, `progress()`, `done()`)를 두고 TUI와 CLI가 각자 구현한다. 나중에 `rich.Live`로 바꿀 수 있다.

### C10. 화면 오류 처리: 같은 except 사다리 8번
- `except KeyboardInterrupt / RuntimeError... / APIError / Exception` → `log_exception` + `notice` + `wait` + `return folder_session(...)` 흐름이 8번 반복된다. 화면 끝에서 `folder_session`으로 돌아가는 코드는 16곳이다. `cli()`와 `run_with_client`도 같은 분기를 따로 갖고 있다.
- 통합: `guarded(context)` 컨텍스트 매니저나 데코레이터 하나로 묶는다. 사용자에게 보여 줄 오류는 `UserError` 하나로 통일한다(지금은 `fail()`이 `RuntimeError`를 쓰므로 진짜 버그와 구분되지 않는다).

### C11. 경로 입력 파싱: 4벌
- `split_pasted_paths`, `clean_path`, `normalize_drop_paths`(`strip('"')`), `term.open_result`.
- 통합: `parse_paths(text) -> [Path]` 하나로 모은다. 드롭, 붙여넣기, CLI 인자가 같은 함수를 쓴다.

### C12. 비용 계산: 5벌
- `estimate_values`, `mixed_preview_lines`(인라인 계산), `cost_lines`, `mixed_cost_lines`, `usage_entry`.
- 통합: C5의 계획(Unit 목록)에서 예상 비용을, 결과 행에서 실제 비용을 계산한다. 함수는 두 개면 된다.

### C13. 플랫폼 분기와 한국어 문구: 4개 언어
- 앱 코드의 플랫폼 분기가 39곳이다. 런처는 cmd, ps1, sh, swift 네 언어로 되어 있고, 한국어 문구도 ps1, sh, swift, Python 네 곳에 흩어져 있다. 그래서 `.cmd` ASCII 규칙, BOM 규칙(D19)이 필요해졌다.
- 통합: uv 전환 뒤 런처는 "uv를 실행한다"만 한다. **Python이 뜨기 전에 보여 줄 한국어 문구는 최소로 줄이고**, 나머지는 모두 Python이 맡는다.

### C14. 빌드: Windows 두 변종과 macOS 스크립트의 중복
- `build_windows.py`(821줄, thin과 offline)와 `build_macos.py`(305줄)에 `log`, `sha256`, 버전 읽기, `bootstrap_env`, `write_manifest`가 각각 있다.
- 통합: `release_common`에 공통 payload, manifest, 해시를 두고 플랫폼 래퍼만 남긴다. offline 변종은 uv 캐시를 미리 채운 ZIP으로 대체할지 §5 D1에서 결정한다.

### C15. 패키지 네임스페이스: 겉보기만 분리됨
- `import nalmeok as app`, 수동 `_MAP` 300줄, 모듈마다 star import, `__init__`의 재노출 줄이 있다. 테스트가 `mock.patch.object(app, ...)`를 **150곳**에서 쓰기 때문에 모든 호출이 `app.` 전역을 거친다. 함수 하나를 추가할 때마다 `__init__` 세 곳을 고쳐야 한다. `nalmeok.cli`는 모듈 이름이 함수에 가려진다(F811).
- 통합: 일반 import로 바꾸고, 테스트는 `patch("nalmeok.engine.x")`로 고친다. §4 구조로 옮길 때 함께 한다.

## 3. 채택한 대안

### 3-1. uv로 런타임 일원화
- 런처는 `uv run --frozen --managed-python --project <앱 폴더> -m nalmeok`을 실행한다.
- Python(python-build-standalone)과 google-genai, av를 `uv.lock`의 해시대로 설치한다. 시스템, Homebrew, pyenv Python은 쓰지 않는다(`--managed-python`).
- 제거 대상: `bootstrap.ps1`, `bootstrap.command`, `bootstrap.env`의 PBS 항목, `ensure_sdk/restart/venv_path/project_python/python_usable/update_sdk`, `messages.ps1`의 Python 관련 문구, macOS `find_python`.
- 업데이트: 앱 payload(코드, `pyproject.toml`, `uv.lock`)를 교체하고 다음 실행 때 `uv run`이 lock에 맞춰 동기화한다. SDK 버전은 lock이 정한다.

### 3-2. PyAV로 ffmpeg 제거
- 2026-11-02 macOS arm64 실측 결과는 다음과 같다(`av 19.0.2`, libavformat 63).
  - 3분 AAC MP4를 M4A로 스트림 복사하는 데 0.017초 걸렸고 길이가 정확했다.
  - 구간 자르기(60초 시작, 60초 길이) 결과가 정확했다.
  - 설치 크기는 약 46MB다(현재 Windows ffmpeg 다운로드는 160MB).
- 제거 대상: `find_tool`, `ensure_ffmpeg`, `probe_duration`의 ffprobe 호출, `split_audio_ranges`의 subprocess 호출, `NALMEOK_FFMPEG`, manifest의 ffmpeg 섹션, `bootstrap.ps1 -Ffmpeg`, 오프라인 번들의 ffmpeg, macOS brew 안내.
- AAC가 아닌 오디오(드문 경우)는 PyAV 내장 aac 인코더로 다시 인코딩한다.

### 3-3. 백그라운드 감시자 제거
- Batch 작업은 서버에 남아 있다. 대시보드를 열 때 제출된 작업의 상태를 조회하고, 성공했으면 그 자리에서 병합한다. `refresh_remote` 경로를 확장하면 된다.
- 제거 대상: `start_watcher/stop_watcher/watcher_running/process_alive/background_wait`, `_wait` 진입점, PID·claim·status·log 파일, `watching` 단계, `progress_screen`.
- 잃는 기능: 앱을 꺼 둔 동안의 자동 병합과 알림. CLI `nalmeok wait`(포그라운드)는 스크립트용으로 남긴다.
- 혼합 작업(B8)은 무료 부분이 끝나면 유료 Batch를 제출하고 바로 돌아온다. 마무리는 대시보드가 한다.

## 4. 제안 모듈 구조 (§2 통합 결과)

```
nalmeok/
  config.py      경로(platformdirs), 설정 파일, 키 저장(keyring 검토)
  keys.py        KeyPool                                   ← C8
  media.py       PyAV: scan_folder · probe · extract · cut  ← C3 C4
  plan.py        순수 함수: Unit 계획 · 배분 · 예상 비용     ← C5 C12
  job.py         JobStore(.nalmeok/), 보관, 결과 병합·저장  ← C6 C7
  gemini.py      업로드(만료 캐시) · generation_config · live 호출 · Batch 제출/조회  ← C6
  runner.py      계획 → 업로드 → free unit 실행 → paid 제출 → 조회 → 병합
  report.py      Reporter(TUI/CLI 진행 표시)              ← C9
  errors.py      UserError, guarded()                     ← C10
  paths.py       parse_paths                              ← C11
  ui/            term 기본 요소 + screens (runner·job·plan만 호출)
  cli.py
  update.py      manifest + payload 교체                   ← C2
```

의존 방향은 `ui/cli → runner → gemini · media · job · plan → config · keys`다. 아래 계층은 위 계층을 import하지 않는다. 테스트는 `plan`과 `job`(순수 함수와 파일 I/O)을 중심에 두고, `gemini`는 가짜 클라이언트 하나로 대체한다.
