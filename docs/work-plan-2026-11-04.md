# 2026-11-04 작업 계획: 성능 · 창 크기 · 접근성

> 상태: **계획.** 아직 고친 코드는 없다.
> 출처는 두 가지다. 하나는 `docs/work-notes-2026-11-03.md`(창 크기 버그, 접근성)이고, 다른 하나는 다른 에이전트의 성능 지적을 코드와 대조해 확인한 결과(2026-11-03 대화)다.
> 성능 지적 가운데 손댈 가치가 있는 4건만 넣었다. 파일 분할과 모듈 전환(work-notes 8-3, 8-6)은 **하지 않는다.** 지금 규모에서는 이득보다 회귀 위험이 크다.

## 0. 원칙: 땜빵 패치 금지

갈아엎지 않는다. 다만 증상이 보이는 자리에 예외 처리를 덧대지 않는다.

1. **원인이 있는 자리에서 고친다.** 예를 들어 창 크기 버그는 "닫을 때 480으로 강제"하는 식으로 덮지 않는다. 폭을 읽는 순서를 바로잡는다. 이벤트 폭주는 호출하는 쪽 여러 곳에서 막지 않고, 이벤트를 받는 한 곳(`refreshItems`)에서 모은다.
2. **이미 있는 구조를 먼저 쓴다.** 같은 일을 하는 함수나 구역이 있으면 거기에 넣는다. 지금 있는 것들은 이렇다.
   - Go: `store.Update`, `runner.update`, `setDetail`, `cachedUpload`, `Batch.Uploads`의 무효화 경로
   - 프런트: `app.js` 구역(Rows, Pane, Row actions, Context menu, Sheets…), `rowState`, `state` 객체, 위임 이벤트, `t()`
3. **같은 규칙이 두 곳에 생기면 한 곳으로 모은다.** 특히 행 동작(스와이프, 행 버튼, 우클릭 메뉴, 키보드)과 포커스·알림 처리가 그렇다. 새 파일을 만들지 않고, `app.js` 안에 구역 하나를 두고 다른 곳이 그것을 부른다.
4. **플래그나 특수 분기로 끄고 켜지 않는다.** "이 경우만 예외" 분기를 추가하고 싶어지면, 그 분기를 만들게 하는 원인부터 찾는다.
5. **고친 이유는 코드 주석 한두 줄로 남긴다.** 특히 순서 의존(창 크기)과 저장 시점(Batch 마커)이 그렇다.

## 2. 디스패치 순서

```text
1단계 (병렬)  W1[D] 창 크기   →  P1[D] 저장 줄이기  →  P2[D] 디바운스     (dlaude는 한 번에 하나)
              P4[O] mp4 읽기 (worktree 따로)
2단계         P3[O] 업로드 URI 저장 (P1 뒤)          A-6[O] macOS 메뉴
3단계         A-1[O] → A-2[O] → A-3[O]              A-4[D], A-5[D] (A-1 뒤)
4단계         C: 전체 리뷰(/code-review high) → mac 서명 빌드 → Windows 빌드·실기 → 수동 확인 → PR
```

- **dlaude 호출:** `~/.local/bin/dlaude -p "<지시>" --permission-mode acceptEdits --allowedTools "Read" "Edit" "Grep" "Glob" "Bash(go build:*)" "Bash(go test:*)" "Bash(go vet:*)" "Bash(gofmt:*)"`
  - 지시에는 반드시 다음을 넣는다: 고칠 자리, 건드려도 되는 파일, 완료 기준, 0절 원칙(땜빵 금지, 기존 구조 사용).
- **Opus 서브에이전트:** `isolation: "worktree"`로 돌리고, C가 리뷰한 뒤 합친다. 같은 파일을 건드리는 O 묶음은 동시에 돌리지 않는다.
- **리뷰 기준(C):** diff에서 다음이 보이면 되돌려 다시 시킨다.
  - 증상 자리의 특수 분기
  - 같은 일을 하는 함수의 중복
  - 덧붙인 CSS 덮어쓰기 블록
  - 이유 없는 새 파일
- **커밋:** 묶음마다 C가 확인하고 커밋한다(Co-Authored-By 없음). 메시지는 `perf(store): …`, `fix(pane): …`, `feat(a11y): …` 형식이다.
- **API 비용:** P3 확인은 가짜 클라이언트 테스트로 한다. 실제 API는 마지막에 무료 키로 짧은 클립 1회만 돌린다. 유료는 쓰지 않는다.
